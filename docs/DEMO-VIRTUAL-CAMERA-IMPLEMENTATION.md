# SentinelVision - Demo Virtual Camera Layer Implementation & Final Demo Guide

## Overview

This document describes the implementation of the **DEMO / VIRTUAL CAMERA** layer (`v_cam01` through `v_cam30`) added to SentinelVision for the final hackathon presentation.

The virtual camera layer allows evaluation videos to feed directly through the **SAME production AI pipeline** used by real government cameras (`cam01` .. `cam30`), ensuring that all dashboard analytics (vehicles, tracks, plate reads, global vehicles, cross-camera sightings, and watchlist alerts) are generated by actual AI execution with **zero fake/mocked data**.

---

## 1. Virtual Camera Architecture & Catalogue Mapping

### Security & Isolation Rules
1. **Additive Layer**: Real government RTSP cameras (`cam01` .. `cam30`) remain completely unchanged in RTSP credential handling, catalogue metadata, and GIS coordinates.
2. **Explicit UI Differentiation**: All virtual cameras are explicitly assigned IDs `v_cam01` .. `v_cam30` and flagged with `is_virtual: true` and `status: "DEMO"`.
3. **Zero File Duplication**: Multiple virtual camera endpoints map to physical source video files without creating duplicate MP4 copies.

## 2. Production AI Pipeline & Looping Engine

### End-to-End Processing Flow
Virtual cameras process frames through the identical pipeline used for RTSP streams:
$$\text{Video File} \xrightarrow{} \text{CameraIngestionWorker} \xrightarrow{} \text{LivePipeline} \xrightarrow{} \text{YOLO11m} \xrightarrow{} \text{ByteTrack} \xrightarrow{} \text{ClassStabilizer} \xrightarrow{} \text{TrackContinuity} \xrightarrow{} \text{ZoneCounter} \xrightarrow{} \text{YOLOv8n-Plate} \xrightarrow{} \text{EasyOCR} \xrightarrow{} \text{SQLite} \xrightarrow{} \text{AlertEngine} \xrightarrow{} \text{EventHub} \xrightarrow{} \text{React Dashboard}$$

### Continuous Video Looping
When a virtual video stream reaches EOF:
1. `VideoCapture.set(CAP_PROP_POS_FRAMES, 0)` rewinds the stream to frame 0.
2. `pipeline.reset_stream_state()` resets internal tracking state (`ByteTrack`), class stabilizer histories, track continuity maps, and clears session deduplication sets (`_recorded_first`, `_persisted_plates`).
3. Ensures continuous worker processing without track ID collision, duplicate key errors, or worker memory leaks.

## 3. Dashboard UI Enhancements

- **Category Filters**: The Live Monitoring dashboard features quick filters for:
  - **ALL CAMERAS**
  - **REAL GOVERNMENT** (`cam01` .. `cam30`)
  - **DEMO / VIRTUAL** (`v_cam01` .. `v_cam30`)
- **Card Badges**: Virtual cameras display prominent amber **`DEMO`** badges and a `smart_display` icon.
- **Inspector Notification**: Selecting a virtual camera displays a **`DEMO / VIRTUAL CAMERA SOURCE`** notice bar highlighting that the feed is a recorded evaluation clip running through production AI.

## 4. Final Demo Verification Walkthrough

Execute the following commands to launch the system for the final hackathon presentation:

### Step 1: Start Backend API
```bash
python -m uvicorn backend.api.main:app --port 8000 --reload
```

### Step 2: Start Frontend Dashboard
```bash
cd frontend/sentinelvision
npm run dev
```

### Step 3: Hackathon Presentation Flow
1. **Real Government Camera (`cam01`)**:
   - Select `cam01` in Live Monitoring to display the real RTSP government camera feed with live vehicle tracking.
2. **Virtual ANPR Camera (`v_cam01`)**:
   - Click the **DEMO / VIRTUAL** filter tab and select `v_cam01`.
   - Observe live license plate detection bounding boxes and OCR text extraction.
3. **Plate Search**:
   - Navigate to **ANPR / Plate Search** page and search for a recognized plate to view timestamp, confidence, and snapshot evidence.
4. **Cross-Camera Vehicle Identity (`HR19R6697`)**:
   - Select `v_cam02` (Gate A) and `v_cam05` (Gate B).
   - Search `HR19R6697` in **Global Vehicles / Vehicle History** to demonstrate cross-camera re-identification across camera locations.
5. **Watchlist Alerts**:
   - Add a demo plate (e.g. `HR19R6697` or recognized plate) to **Watchlist**.
   - Stream `v_cam01` or `v_cam02` to trigger an instant real-time alert pop-up via WebSockets.
6. **GIS Map & Telemetry**:
   - Open **GIS Map** to view camera markers (Real vs Demo) and vehicle sighting routes.
   - Open **System Health** to inspect real-time CPU/GPU/memory and worker processing telemetry.
